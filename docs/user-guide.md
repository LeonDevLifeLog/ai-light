# AI-Light 用户手册

AI-Light 将 Claude Code、Codex 等 AI 编程工具的运行状态转换为 AgentCore-Light 的灯效与提示音。本手册只描述日常使用；主题文件格式、Hook API 和架构设计请从[项目文档导航](./README.md)进入。

## 1. 首次使用

1. 启动 AI-Light。主窗口关闭后应用仍驻留在系统托盘，可从托盘重新打开或退出。
2. 进入「设备」，点击扫描并连接 AgentCore-Light。连接成功后，应用会自动读取设备信息并恢复状态灯输出。
3. 进入「接入」，为 Claude Code 或 Codex 点击「连接」。AI-Light 会安装或检测 Adapter，并把自己的 Hook 安全合并到对应工具配置中。
4. 回到「状态」，确认设备、当前业务状态和主题均已就绪。

Codex 首次执行 Hook 时，仍可能要求按 Codex 自身的安全机制确认信任。点击「断开」只会移除 AI-Light 管理的 Hook，不会删除工具的其他配置。

## 2. 状态灯代表什么

AI-Light 使用五个标准状态：

| 状态 | 含义 | Default 经典主题 |
|---|---|---|
| 空闲 `IDLE` | 当前没有需要展示的任务状态 | 熄灭 |
| 工作中 `WORKING` | 工具正在处理任务 | 三灯依次蓝色呼吸 |
| 等待中 `WAITING` | 工具正在等待用户输入或确认 | 琥珀色慢呼吸 |
| 已完成 `SUCCESS` | 最近一次任务成功结束 | 绿色常亮，持续到下一状态 |
| 出错了 `ERROR` | 最近一次任务执行失败 | 红色闪烁后常亮，并提示一声 |

不同主题可以改变颜色、动画、亮度、提示音和终态驻留方式，但应保持状态之间的视觉区分。部分主题的成功状态会在设定时间后自动回到空闲；Default 经典主题的成功和错误状态会持续显示，直到收到下一次状态事件。

## 3. 多个工具同时运行

多个工具同时上报时，AI-Light 固定采用「最近活动优先」：最后上报状态的工具接管灯效。该行为没有可切换的设置项。

例如，Claude Code 正在工作时，如果 Codex 随后进入等待输入，灯会显示 Codex 的等待状态；用户完成输入后，只要 Codex 上报新的工作状态，灯就会再次显示工作中。状态的视觉强弱只用于帮助辨认，不参与工具之间的抢占判断。

## 4. 管理主题

在「主题」页面可以：

- 切换六套内置主题或已保存的用户主题；切换后立即按当前业务状态更新灯效。
- 以当前主题为基础创建用户主题，分别调整五个标准状态及自定义状态。
- 导入 `.ailight-theme.json` 文件；主题标识不得与内置主题同名。
- 删除用户主题。内置主题属于应用资源，不能删除，也不会显示删除入口。

删除操作不可恢复。删除当前正在使用的用户主题时，AI-Light 会先切换到内置的 Default 经典主题，再删除主题文件；如果删除失败，原主题会保留或尝试恢复。

## 5. 试听与自定义状态

「试听」页面可以手动触发空闲、工作中、等待中、已完成和出错状态，用于检查当前主题和设备效果。手动试听与外部工具遵循同一套最近活动规则，因此试听操作也会成为最近一次状态来源。

自定义状态只有在当前主题存在对应映射时才会显示专属效果；未映射时回退为空闲效果。

## 6. 设置

「设置」页面提供：

- 外观模式：亮色、暗色或跟随系统。
- 灯组朝向：调整界面中三灯的排列方向。
- 当前主题入口：查看当前主题并前往主题中心。
- 开机自启：控制 AI-Light 是否随系统登录启动。
- 高级服务信息：打开当前 Hook API 文档。

设置修改后立即生效并自动保存。服务端口由 AI-Light 自动管理，普通使用无需手动配置。

## 7. 常见问题

### 灯没有随工具状态变化

依次确认设备已连接、对应工具在「接入」页面显示已连接，并检查当前主题是否定义了该状态。也可以先在「试听」页面触发标准状态，以区分设备连接问题和工具接入问题。

### 成功状态为什么没有自动熄灭

终态是否自动回到空闲由主题决定。Default 经典主题把成功状态保留到下一次事件，便于稍后仍能看到任务结果；其他主题可能配置自动回落。

### 为什么找不到多工具优先级设置

AI-Light 只采用最近活动优先，不再提供其他仲裁策略，因此设置页没有该选项。

### 为什么内置主题不能删除

内置主题随应用分发，并承担默认回退能力。只有用户创建或导入的主题可以删除。
