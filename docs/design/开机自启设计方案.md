## 1. 背景与目标

产品形态为托盘常驻（KAD-06）：关窗 = 隐藏、退出只经托盘。作为常驻工具，用户预期"登录系统后灯效服务自动就位"，无需手动打开。本期目标：把开机自启做成**真实可切换的设置项**（Settings 页 Switch 真实化），与 config 持久化、OS 登录项保持双向一致。

## 3. 方案总览

### D-01 OS 登录项 = 唯一事实源；`config.autostart` = 启动校准缓存

OS 登录项（macOS LaunchAgent / Windows Run key / Linux XDG autostart）才是"开机是否自启"的真值。`config.json` 里的 `autostart` 只做**启动校准缓存**：每次启动用 `is_enabled()` 校准并写回，二者短暂不一致（用户手动改系统登录项、配置文件被外部编辑）时以 OS 为准。

### D-02 不引入 JS 绑定，统一走 Rust `update_config`

不安装 `@tauri-apps/plugin-autostart` 前端绑定。理由：前端直接调 `enable()/disable()` 会绕过 config 一致性（config 不会更新、`config-changed` 不会 emit）。所有自启动变更统一经 `update_config(autostart)` 一个入口：**先 OS 操作，成功后写 config + emit `config-changed`；失败返回错误码，config 保持原值**。

### D-03 插件选型：官方 `tauri-plugin-autostart` v2（当前 2.5.1）

`src-tauri/Cargo.toml` 增加 `tauri-plugin-autostart = "2"`，并在 `Builder` 上注册。

> **方案修订说明（纠正此前口头表述）**：官方 crates.io 版本**不存在** `macos-launch-at-login` feature（2.5.1 的 features 为空）。该插件 macOS 端走 `auto-launch` crate 的 **LaunchAgent**（默认）或 AppleScript 登录项，**不是 SMAppService**——因此**不要求正式签名**，ad-hoc 签名的 dev / CI 构建可直接生效。SMAppService 迁移留作 V2 备选（见 O-2）。

### D-04 平台机制与签名约束

| 平台 | 机制 | 落点 | 签名要求 | 已知注意点 |
|---|---|---|---|---|
| macOS | LaunchAgent（`MacosLauncher::LaunchAgent`，默认） | `~/Library/LaunchAgents/com.<identifier>.plist` | 无（ad-hoc 可用） | Ventura+ 首次启用会弹一次"在后台运行"系统通知（体验层验收项）；app 被移动后 plist 指向旧路径可能失效（实机验证） |
| Windows | Registry Run key | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` | 无 | 路径含空格需引号（`auto-launch` 已处理）；杀软可能拦截自启（体验层） |
| Linux | XDG autostart | `~/.config/autostart/<app>.desktop` | 无 | 依赖桌面环境（GNOME/KDE 等）对 autostart 的支持；AppImage 场景插件已特殊处理路径 |

### D-05 启动校准时序（setup 内）

Tauri 插件 `setup` 回调先于应用 `.setup()` 执行，注册插件后应用 setup 内即可安全调用 `app.autolaunch().is_enabled()`：

1. 加载 `config.json`（现有逻辑不变）
2. `is_enabled()` 读取 OS 登录项 → 写回 `cfg.autostart`
3. 读取失败**不阻塞启动**：记日志、保留本地缓存值
4. 前端 `get_config` / `config-changed` 拿到校准后的值

### D-06 切换时序（update_config）

```text
Settings Switch ──> update_config({ autostart: true })
                        │
                        ▼
                plugin.enable() / disable()   ← OS 操作先行
                        │
           ┌────────────┴────────────┐
           ▼ 成功                    ▼ 失败
   cfg.autostart = b          Err(AUTOSTART_FAILED,
   persist_config(cfg)           message=OS 错误)
   emit config-changed      config 保持原值，前端 toast
```

### D-07 登录启动参数 `--autostart`（预留）

注册插件时传入 `--autostart` 参数（`Builder::new().args(["--autostart"])`），使登录启动与手动启动可区分（与单实例回调收到的 args 配合）。**本期行为与手动启动一致（显示主窗口）**，该参数仅预留，供后续"登录启动不弹窗/托盘驻留"优化使用（见 O-1）。

## 4. IPC 契约变更

`docs/specs/ipc-contract.md`：

- §2.5：`update_config` 错误码补 `AUTOSTART_FAILED`
- §3：`autostart` 注释从"KAD-06 SHOULD"改为"OS 登录项为事实源，config 为校准缓存"
- §4 错误码表新增：

| code | 含义 | 场景 |
|---|---|---|
| `AUTOSTART_FAILED` | OS 登录项操作失败 | update_config(autostart) 时 enable/disable 抛错（权限、路径失效、平台异常等） |

- §8 对账快照：`autostart` 状态从"仅持久化"改为"已接插件（校准缓存语义）"

## 5. 前端改动（settings.tsx）

- 移除 `disabled` 与「待平台支持」StatusTag，改为真实 Switch，`checked = config.autostart`
- `onCheckedChange` → `updateConfig({ autostart })`
- 失败（`AUTOSTART_FAILED`）：复用现有 toast 机制提示"开机自启设置失败"，Switch 回弹为 config 原值
- 订阅 `config-changed`（已有基础，app-context 已订阅）保持状态同步
