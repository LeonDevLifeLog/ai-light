# ADR-0005：最近活动唯一仲裁策略

- 状态：已接受
- 日期：2026-08-30
- 取代：ADR-0001 Q8 的“优先级抢占可配置”部分、KAD-12

## 背景

实机联调显示，优先级抢占会让较高优先级的旧状态阻止较低优先级的新状态上屏。尤其在工具等待用户输入后，即使用户已经完成输入，灯效仍可能无法回到工作中。依赖 `source` 判断“同一工具”的修补无法覆盖实际接入中的全部来源标识与并发路径。

## 决策

状态仲裁固定为最近活动优先：任何来源的新非幂等状态都接管当前灯效。客户端不再提供仲裁模式设置，`config.json` 和 `update_config` 不再暴露 `arbitrationMode`。旧配置中的 `arbitrationMode` / `arbitration_mode` 作为未知字段忽略，下一次保存配置时自然移除。

标准状态的强度顺序 `ERROR > SUCCESS > WORKING > WAITING > IDLE` 仅用于主题视觉语义，不参与事件是否上屏的判断。

## 后果

- 多工具并发行为唯一且可预测：最后上报者接管灯效。
- `WAITING → WORKING` 等生命周期推进不再依赖来源标识一致性。
- 取消运行时模式切换及其配置、IPC、UI 和测试分支。
- 历史 ADR 保留，用本 ADR 表达决策演进。

## 验证

- 回归测试覆盖较低视觉强度的新状态覆盖旧 `ERROR`，并覆盖不同来源连续接管。
- 前端设置页不再渲染“多个工具同时运行时”。
- Rust 配置序列化结果不再包含 `arbitrationMode`，旧字段仍可被安全读取。
