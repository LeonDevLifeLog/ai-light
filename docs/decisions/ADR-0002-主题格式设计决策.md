## 背景

主题 = `状态 → SCENE` 映射表（ADR-0001 已确认：本地 JSON 配置文件、UI 可编辑、可分享导入）。本轮确定主题文件的具体格式结构。

## 决策（6 项，全部按建议确定）

### T-01 SCENE 结构：命名 SCENE 库 + 引用

**确定：主题文件分两段——`scenes`（命名 SCENE 库）+ `states`（状态 → SCENE 名引用）**

- 复用：同一灯效（如 `breath-blue`）可被多个状态引用；改一个 SCENE 全局生效
- 编辑器友好：未来可视化编辑器操作的原子对象就是 SCENE
- 反对内嵌：同效果写 N 遍，不可维护

### T-02 transition_ms：状态级配置

**确定：切换过渡时长（transition_ms）挂在状态映射上（`WORKING: { transition_ms: 300 }`）**

- 语义：进入不同状态的过渡节奏不同（ERROR 切换干脆、WORKING 柔和渐变）
- 不进 SCENE：过渡是"状态间切换"的行为，不是灯效本身

### T-03 状态级覆盖：第一期不做

**确定：保持"状态 = 引用一个 SCENE"的简单模型，不支持状态级字段覆盖（如降亮度）**

- 需要不同亮度/变体 → 新建 SCENE
- 理由：覆盖引入"合并规则"复杂度，主题作者易困惑；第一期不需要

### T-04 蜂鸣轨道：可选

**确定：`buzzer` 字段可选，`null` = 静音；大部分状态不需要声音**

- 避免强制空数组噪音

### T-05 自定义状态：随用随写（松散）

**确定：不要求主题声明状态列表；自定义状态名直接在 `states` 中写**

- 容错：客户端遇到主题中未映射的状态 → 显示 IDLE + 记日志
- 理由：声明列表增加维护负担，且校验失败难排查

### T-06 校验与容错：整体校验 + 默认主题兜底

**确定：主题加载时整体校验；任一 SCENE 字段非法 → 整个主题拒绝生效，回退内置默认主题**

- 与 V0.4"任一参数非法，全部不改"的原子哲学一致
- 默认主题（内置 5 态基础灯效）随客户端分发，作为兜底

## 后果

- **正面**：主题格式简单一致（SCENE 库 + 引用），人可读写、UI 可编辑、可分享；与 L2 编译链路（状态 → SCENE 名 → JSON → V0.4 二进制）清晰对应
- **负面**：第一期无状态级覆盖，个别需求（同效果不同亮度）需多建 SCENE——可接受
- **待定**：高级直控通道（direct_scene 预留枚举，V2 实现）
